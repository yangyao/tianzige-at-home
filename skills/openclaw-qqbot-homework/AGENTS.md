## 作业上传（家里的田字格）

**语气约定：** "传回家"、"上传作业"、"传到 NAS" 都是指同一个动作——把作业图片交给家里的作业服务，没有额外的归档、备份或存储操作。回复用户时说人话，只说"已传回家"、日期和作业内容；**不要**提 NAS、服务器、curl、批次接口、识别引擎等技术细节，也不要提醒任何凭证或配置。批次号（batch_id）可以提，方便用户撤回。

**先判断，再上传。** 收到图片后，先用视觉能力看图，判断它是否是作业相关照片：黑板上的作业、练习册/试卷/课本页面、老师拍的作业板书等。以下情况**不要上传**，正常聊天即可：

- 风景、宠物、表情包、截图、自拍、美食等明显非作业内容
- 内容模糊到看不清是不是作业
- 你不确定它是不是作业

不确定时，先问一句"这张要传回家当作业吗？"，用户确认后再传。用户明确说了"传回家/上传作业"，则跳过判断直接传。

判断为作业图片后的上传流程：

1. 找到消息里的图片文件（OpenClaw 已保存到本地，路径会随消息给出，通常在 `media/` 或 `~/.openclaw/media/qqbot/` 下）。
2. 执行上传，**不要轮询结果**（把 `<服务器地址>` 换成实际的 homework-server 地址）：

```bash
curl -sS -F "files=@<图片路径>" -F "note=<老师配的文字，没有则省略>" \
  http://<服务器地址>/api/ingest
```

多张图片可重复 `-F "files=@..."`，一次最多 6 张。

3. **日期**：默认传服务端当天即可；但如果用户提到"星期一/周二/昨天/前天"等日期词，必须换算成具体的 `YYYY-MM-DD` 并传 `-F "date=YYYY-MM-DD"`（例如用户周三说"这是周二的作业"，就传周二的日期）。拿不准是哪天时，先问用户再传。
4. 返回 202 表示已落盘、后台识别中。回复用户：批次号 `batch_id`、日期、图片张数，并说明"识别完成后电视上就能看到"。`duplicate_of` 有值说明之前传过，直接告知。
5. 上传失败时把 `error.message` 原样告诉用户，不要编造成功。
6. 不要主动删除批次或调用 rerun，除非用户明确要求。
