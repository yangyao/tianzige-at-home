# 上传端 UI 规范

> 适用于 iOS、macOS、Web 三个上传端。色彩字号取 [`tokens.json`](tokens.json)。
> 电视端规范不在这里，见 [`04-电视端UI.md`](../docs/04-电视端UI.md)。

## 1. 三端共同的信息架构

只有一个页面，四个区块，从上到下：

```
┌─────────────────────────────┐
│ 家里的田字格        [设置 ⚙] │  ← 标题行
├─────────────────────────────┤
│                             │
│      ＋ 添加图片             │  ← 上传区（见 §2）
│                             │
├─────────────────────────────┤
│ [缩略图][缩略图][缩略图] ✕✕✕  │  ← 已选图片条
├─────────────────────────────┤
│ 老师的话（选填）____________  │  ← 备注输入框
│ 日期 [今天 ▾]                │  ← 日期（默认今天，可改昨天）
│ [ 上传（3 张） ]             │  ← 主按钮
├─────────────────────────────┤
│ 最近上传                     │  ← 仅 Web 有，见 §5
└─────────────────────────────┘
```

## 2. 上传区：三端各自的「添加」方式

| 端 | 支持的添加方式 | 优先级 |
|---|---|---|
| Web | **⌘V 粘贴**（一等公民）、拖拽、文件选择 | 粘贴 > 拖拽 > 点选 |
| iOS | 相册多选（`PHPickerViewController`）、**拍照**（`UIImagePickerController` camera）、读剪贴板图片 | 相册 > 拍照 > 剪贴板 |
| macOS | **拖拽到窗口/Dock 图标**、⌘V、文件选择；菜单栏图标点击直接弹窗 | 拖拽 > ⌘V > 菜单栏 |

上传区空态文案：

- 主文案：`把作业照片放进来`
- 副文案按端写：Web「截图后按 ⌘V 直接粘贴」/ iOS「从相册选，或直接拍」/ macOS「拖进来，或按 ⌘V」

约束：单批 1–6 张，单张 ≤ 20MB，jpg/png/heic/webp。
超限**不要弹 alert**，在上传区下方用一行红字提示，已有的合法图片保留。

## 3. 核心流程：提交即走

```
选图 → （可选）填老师的话 → 点「上传（N 张）」
  → 按钮变「上传中…」并禁用（这个状态只持续到 202 返回，通常 <1s）
  → 收到 202：立即清空表单 + toast「收到 N 张，处理完电视上就有」
  → 用户此时关页面/切走，没有任何损失
```

四条铁律：

1. **上传端不轮询识别结果**。`/api/ingest` 返回 202 就结束，识别是 NAS 的事。
2. **toast 只在 4xx/5xx 时改成可重试**：网络错误 →「没传上去，点这里重试」，保留已选图片，一键重发。
3. 上传请求**带超时 30s**，超时按失败处理，同样保留图片可重试。
4. 日期默认今天；补传昨天是真实场景，日期选择器必须有，但收进「日期」一行，不做日历弹层（Web 用 `<input type="date">`，iOS 用 `DatePicker` wheel，macOS 用 `DatePicker`）。

## 4. 各端特有要求

### iOS（`apps/upload-ios`，SwiftUI，最低 iOS 16）

- 单手可达：主按钮固定在底部安全区上方
- 图片预览：横向滚动条，每张右上角 ✕ 删除
- **不需要**「最近上传」列表、重跑、删除批次——手机只负责送进来
- 剪贴板检测：`UIPasteboard` 有图片且 App 进前台时，轻提示「检测到剪贴板图片，要添加吗？」，
  **iOS 16+ 读剪贴板会弹系统权限提示，必须由用户点确认后再读**，不要自动读
- 设置页：NAS 地址输入框（`http://192.168.x.x:8080`），存 `UserDefaults`，带连通性测试按钮（`GET /api/health`）

### macOS（`apps/upload-mac`，SwiftUI，最低 macOS 13）

- 形态：**菜单栏 App**（`MenuBarExtra`），不开 Dock 常驻窗口
- 菜单栏菜单：`打开上传窗口` / `最近一次上传：✓ 3 张 · 17:32`（只读状态） / `设置…` / `退出`
- 拖拽目标：上传窗口全窗可拖（`onDrop`），Dock 图标接受文件（`onOpenFile`）
- 拖拽多文件直接进「已选图片」条
- 设置窗口：NAS 地址 + 测试连接
- 同样**不做**最近上传列表

### Web（`apps/upload-web`，单文件 HTML，零依赖零构建）

- 已有实现 `upload.html` 作为基准，本次按新协议改造
- 「最近上传」列表：最近 6 批，显示 `日期 · N 张 · 状态`；`failed` 的行给「重新识别」按钮，`done` 的给「删除」
- 手机浏览器打开也要能用（响应式，>=360px）
- 上传用 `XMLHttpRequest`（要上传进度百分比，`fetch` 不给上传进度）

## 5. 状态与文案

| 情况 | 显示 |
|---|---|
| 上传中 | 按钮 `上传中…`，禁用 |
| 202 成功 | toast `收到 N 张，处理完电视上就有`，6s 自动消失 |
| 全部图片与已有批次重复（`duplicate_of` 有值） | toast `这些图片之前传过了，没有重复入库` |
| 网络失败 | 按钮变红 `没传上去，点这里重试`，图片保留 |
| 服务不通（health 失败） | 顶部一条黄条 `连不上 NAS，检查地址或网络` |
| 识别失败（仅 Web 列表里可见） | 行内 `这次没识别出来` + `重新识别` 按钮 |

文案原则见 [`DESIGN.md` §9](DESIGN.md)：主文案说结论，副文案给出路，不出现 OCR、批次等技术词。

## 6. 不做的事

- 不做登录、不做账号（局域网自用）
- 不做图片编辑、裁剪、滤镜——老师拍什么样就传什么样
- 不做推送通知
- iOS 不做 Today Widget / Shortcuts 自动化（以后想要再说）
- macOS 不做自动监听文件夹（QQ 抓取由 Mac mini 上的 Codex 负责，走 `POST /api/ingest`，那是另一条路）
