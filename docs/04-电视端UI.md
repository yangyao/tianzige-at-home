# 电视端 UI 规范

设计稿：`design/tv-ui-design.html`（浏览器打开，底部按钮切 6 种状态，可显示尺寸标注）

画板 1920 × 1080，安全边距 60px。

## 1. 分区

```
┌──────────────────────────────────────────────┐
│ 今天的作业   2026年11月12日 星期四   [已同步] │ 96px
├──────────────────────────────────────────────┤
│ ‹  [周一10] [周二11] [●周三12] [周四13] …  ›  │ 104px  日期条
├───────────────────────────┬──────────────────┤
│                           │  数学  2/3       │
│        原图 1090×714      │  ─────────────   │
│                           │  1 练习册 P18…   │  714px
│                           │  2 口算本一页…   │
│                           │  3 家长签字      │
│                           │  识别结果仅供参考 │
├───────────────────────────┴──────────────────┤
│ ← → 换日期   ↑ ↓ 换科目   OK 看大图  返回 退出 │ 66px
└──────────────────────────────────────────────┘
```

## 2. 交互模型

**只有日期条参与焦点，内容区不参与。** 这是整个设计最重要的决定——TV 应用最常见的失败是「焦点在哪儿」。

| 键 | 动作 |
|---|---|
| ← → | 换日期（跨周自动翻） |
| ↑ ↓ | 换当天的第几张图 / 第几科 |
| OK | 全屏看原图；再按 1x / 2x |
| 返回 | 全屏时关闭；首页时退出 |

四个键覆盖全部功能，没有二级菜单、没有 tab、没有滚动列表。

## 5. 状态

| 状态 | 表现 |
|---|---|
| 今天有作业 | 正常布局，日期条停在今天 |
| 今天还没发 | 大字「今天还没有作业」+ 副文案「老师发出来之后，这里会自己出现」 |
| 看历史日期 | 标题变「9日的作业」，右上角挂「3 天前」角标 |
| 识别未完成 | 只显示原图，文字区显示「正在识别」 |
| 识别失败 | 只显示原图，不报错、不弹窗 |
| 全屏看图 | 纯黑铺满，底部半透明键位提示 |

## 6. 为什么不做月历

一屏 42 格，遥控器从「今天」走到「上周一」要按 30 多下。而 95% 的使用是看今天。

所以：**本周 7 天横条 + 两端 ‹ › 翻周**。日历留给「找很久以前的作业」这种低频需求，真需要时再加一个独立入口。

## 7. 图片处理

- 原图整张显示，`object-fit: contain`，不裁切
- 全屏后可 2x 放大 + 方向键平移
- 黑板字小，全屏是主要阅读方式；分区块浏览（按题目切块）作为 P2
