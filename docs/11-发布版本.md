# 发布版本

`.github/workflows/release.yml` 在推送 `v*` tag 时构建并创建 GitHub Release。版本格式为 `v1.0.0`，预发布可用 `v1.1.0-beta.1`，自动标记为 prerelease。

```sh
git tag -a v1.0.0 -m '家里的田字格 1.0.0'
git push origin v1.0.0
```

两个构建任务都成功后才发布：

- Linux：JDK 17、Android SDK 34、Gradle 8.9，运行 TV 单元测试和 lint；Go 1.23.12 运行 race 测试并打包 Linux arm64 / amd64 NAS 服务。
- macOS：使用 runner 已安装的 Xcode 和 XcodeGen，生成本地签名 Mac 包，以及未签名 iOS App / 标准 IPA。
- 发布：附加所有安装包和 `SHA256SUMS.txt`，自动生成变更说明。

tag 的数字部分写入 Apple 和 TV 应用版本；构建号采用工作流运行序号加 3。已有 tag 不应移动；修复后发布新版本。未签名 Apple 包不会变成 App Store 或公证分发。

电视 APK 沿用目前设备已安装的调试签名，签名文件通过仓库 Actions Secret `ANDROID_DEBUG_KEYSTORE_BASE64` 恢复，不提交源码、不进入发布包。不要删除或更换此 secret，否则无法覆盖安装。此为家庭使用的调试包；未来改为正式签名时需安排迁移。

Actions 页的 **Run workflow** 只构建和上传临时 artifacts，不创建 tag 或公开 Release，可用于验证流程。CI 允许在 GitHub runner 下载工具与依赖，本机离线构建策略不变。没有使用 NAS 的 AI 密钥或用户照片。

重新运行失败工作流会复用该 tag 的 Release，并覆盖同名附件。下载页面：<https://github.com/yangyao/tianzige-at-home/releases>。
