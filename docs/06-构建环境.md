# 构建环境

> 本文记录**在你这台机器上已经验证能构建的版本组合**，来源是你自己仓库里的实际工程。
> 各端实现必须以本文为准，不要用"最新版"或"我猜的版本"。

## 0. 本机（沙箱）能验证什么

写代码前先看这张表，决定哪些结论可以靠"我跑过"来担保，哪些只能靠代码审查。

| 端 | 能否在本机构建 | 环境 |
|---|---|---|
| Go 服务端 | ✅ 能编译、能测试、能真跑 | Go 1.21.4 |
| Android TV | ✅ **能出 APK** | SDK 在 `/opt/android-sdk`（build-tools 34.0.0、platforms/android-34、platform-tools） |
| Web | ✅ 能渲染截图 | Chromium headless |
| iOS / macOS | ❌ 不能 | Linux，无 Xcode / 无 Apple SDK |

Android 构建只需在 `apps/tv-android/local.properties` 写一行 `sdk.dir=/opt/android-sdk`
（该文件已 gitignore，不要入库）。

## 2. Android TV —— 直接用这一套

`navidrome-tv` 与 `apps/tv-android` 是两套**都已经验证能构建**的组合。选一套，不要混。

| 项 | A：本项目 `apps/tv-android`（本机已出 APK） | B：`navidrome-tv`（你机器上已验证） |
|---|---|---|
| Gradle | 8.7 | 8.9 |
| AGP | 8.5.2 | 8.5.2 |
| Kotlin | **1.9.24**（+ `kotlinCompilerExtensionVersion = "1.5.14"`） | **2.0.20**（+ `org.jetbrains.kotlin.plugin.compose`） |
| Compose BOM | 2024.06.00 | 2024.02.02 |
| TV 组件 | `androidx.tv:tv-material:1.0.0` | 无，用普通 `material3` 自己管焦点 |
| compileSdk / minSdk / targetSdk | 34 / 26 / 34 | 34 / 26 / 34 |
| Java / jvmTarget | 17 | 17 |

**本项目用 A**。它在本沙箱里 `./gradlew assembleDebug` 产出过 8.7MB 的 APK，是"跑过"而不是"看着对"。

### 两套的差别，以及什么时候换

- **A 用 `androidx.tv:tv-material:1.0.0`**：卡片、按钮自带焦点放大和描边，"按下有反应"是白送的。
  代价是它自带的焦点样式和设计稿的（4px accent + 外发光）不完全一致，部分组件要用 `Modifier` 覆盖。
- **B 用普通 `material3` + 手写焦点**（`FocusBus.kt`）：控制力最强，每个焦点态都是自己画的。
  代价是每个可聚焦组件都要写一遍 `onFocusChanged` + 边框 + 缩放。

设计稿的焦点态两套都能做。**但不要在同一工程里混用**——一半 tv-material 一半普通 material3，
D-pad 的焦点链会断，按方向键直接跳不动。

### 升到 Kotlin 2.0 时怎么改

照 B 列：`build.gradle.kts` 根插件把 Kotlin / plugin.compose / plugin.serialization 三个都写 `2.0.20`，
删掉 `android { composeOptions { kotlinCompilerExtensionVersion = ... } }` 整块，其余不动。

### `settings.gradle.kts` 的仓库配置必须照抄

```kotlin
pluginManagement {
    repositories {
        google {
            content {
                includeGroupByRegex("com\\.android.*")
                includeGroupByRegex("com\\.google.*")
                includeGroupByRegex("androidx.*")
            }
        }
        mavenCentral()
        gradlePluginPortal()
    }
}
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories { google(); mavenCentral() }
}
```

不这么写在国内网络下拉 `androidx` 会非常慢或超时。

### 国内构建必须加镜像（可选但强烈建议）

`~/.gradle/init.gradle.kts` 或 `gradle.properties` 里配阿里云镜像。不在仓库里硬编码，README 说明即可。

### 明文 HTTP 必须放开

服务端是 `http://`，Android 9+ 默认禁明文。照 `little-learning` 的做法加：

```xml
<!-- res/xml/network_security_config.xml -->
<network-security-config>
    <base-config cleartextTrafficPermitted="true" />
</network-security-config>
```
并在 `<application android:networkSecurityConfig="@xml/network_security_config" ...>` 引用。

### 设置屏的更好做法：学 `navidrome-tv`

`navidrome-tv` 的 `pairing/` 包里已经解决过"电视上没法输入地址"这个问题：

- `PairingServer.kt` —— TV 上起一个临时 HTTP 服务
- `QrGenerator.kt` —— 屏幕显示二维码
- `SetupPage.kt` —— 手机扫码打开的配置页
- `ServerDiscovery.kt` / `LanAddress.kt` —— 局域网地址发现

**本项目 MVP 取舍**：
1. 默认地址 `http://nas.local:8080`（NAS 开了 Bonjour/mDNS 就直接通，大概率无需配置）
2. 兜底：D-pad 数字键盘输入 IP（简单可靠，一次配置）
3. 增强（可选，不阻塞）：照 `pairing/` 的思路做扫码配置

## 3. iOS / macOS

### iOS：必须是 `.xcodeproj`

iOS App 无法用 SwiftPM 打包成可安装的 App。`sony-remote` 和 `little-learning` 都是把
`<Target>.xcodeproj/project.pbxproj` 直接提交进仓库的。

**不要手写 `project.pbxproj`**——UUID 交叉引用极易出错，且报错信息不可读。

交付方式（按优先级）：
1. 源码目录按 `sony-remote` 的形状摆好：
   ```
   apps/upload-ios/
   ├── Config/Info.plist
   ├── Tianzige/{TianzigeApp.swift, Views/, Models/, Services/}
   └── README.md
   ```
2. README 写清 3 步：Xcode → New Project → iOS App (SwiftUI) → 把 `Tianzige/` 目录拖进工程 → 改 Bundle ID + 填 Info.plist 权限键。
   对熟悉 Xcode 的人这是 3 分钟的事，比一个可能打不开的 pbxproj 靠谱。
3. 附 `project.yml`（XcodeGen 格式）作为可选加速路径，`brew install xcodegen && xcodegen` 能直接生成工程。

### macOS：XcodeGen 或 SwiftPM，本项目走 XcodeGen

你已有两条都验证过的路径：

| 路径 | 代表 | 特点 |
|---|---|---|
| **XcodeGen**（`project.yml` → 生成 `.xcodeproj`） | 本项目 `apps/upload-mac/` | Info.plist 完全可控，适合菜单栏 App |
| **SwiftPM**（`Package.swift`） | `nas-media-archiver/apps/macos/` | `swift build` 即可，零额外工具 |

**本项目选 XcodeGen**，原因很具体：菜单栏 App 需要两项 Info.plist 配置——
`LSUIElement=true`（不出现在 Dock）和 `CFBundleDocumentTypes`（接受从 Finder 拖到图标上的图片）。
SwiftPM 无法直接产出带自定义 Info.plist 的 `.app`，得在代码里补 `NSApp.setActivationPolicy(.accessory)`，
Dock 拖拽接收也要绕路。XcodeGen 一行 yml 解决。

代价只有一个：构建前 `brew install xcodegen`。

如果哪天不想装 XcodeGen，删掉 `project.yml`、照 `nas-media-archiver` 的样子补 `Package.swift` 也能跑，
但 Dock 拖拽会退化。**不要同时维护两套工程文件**——漂移起来比装个工具麻烦得多。

## 4. Go 服务端

`nas-media-archiver` 的依赖组合：

```
go 1.20                        （本机 1.21.4，用 1.21 即可）
modernc.org/sqlite v1.29.10    （纯 Go，免 CGO）
```

**必须用 `modernc.org/sqlite`，不要用 `github.com/mattn/go-sqlite3`**——后者要 CGO，
交叉编译到 NAS 会痛死。

### 交叉编译到 NAS

NAS 的 CPU 架构决定目标：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o dist/homework-server-linux-arm64 ./cmd/server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o dist/homework-server-linux-amd64 ./cmd/server
```

在 NAS 上跑之前先确认架构：`uname -m`（`aarch64` → arm64，`x86_64` → amd64）。

`Makefile` 目标照 `nas-media-archiver` 写：`build` / `build-linux-arm64` / `build-linux-amd64` / `test` / `clean`。

### 包结构

`nas-media-archiver` 用的是单 `cmd/` 包 + 平铺的 `service_*.go` 文件。
本项目按 `internal/{store,ocr,parse,pipeline,api}` 分层更清晰，但**不要过度分层**——
总共几千行的服务，目录超过两层就是负担。

### 依赖下载

本机到 `proxy.golang.org` 可能不通，构建时用：

```bash
GOPROXY=https://goproxy.cn,direct go mod tidy
```

`go.sum` 必须提交。README 里注明这条。

## 5. 通用坑（都踩过）

| 坑 | 表现 | 解法 |
|---|---|---|
| Gradle 拉不到 androidx | 卡在 `Downloading` 十分钟 | `settings.gradle.kts` 用上面的仓库配置 + 国内镜像 |
| Android 明文 HTTP 被拦 | 请求直接失败，logcat 有 `Cleartext HTTP traffic not permitted` | `network_security_config.xml` |
| `xcodeproj` 打不开 | Xcode 报 "project is damaged" | 不要手写 pbxproj，按 §3 的方式交付 |
| SwiftPM 做菜单栏 App 没图标 | 出现在 Dock 里 | `NSApp.setActivationPolicy(.accessory)` |
| CGO 交叉编译失败 | `gcc: command not found` | `CGO_ENABLED=0` + 纯 Go sqlite 驱动 |
| Go 拉依赖超时 | `dial tcp ... i/o timeout` | `GOPROXY=https://goproxy.cn,direct` |
| 电视上图画不出来 | Coil 加载失败无提示 | 检查 `http://` 是否被 manifest 的 `usesCleartextTraffic` 拦住 |
