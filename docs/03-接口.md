# 接口索引

> **字段级定义看 [`spec/openapi.yaml`](../spec/openapi.yaml)，那是唯一真源。**
> 本文只做索引和数据库设计，不重复字段说明，避免两处漂移。

Base URL：`http://<nas-ip>:8080`，仅局域网，无鉴权。

## 1. 九个接口一览

| 方法 | 路径 | 用途 | 调用方 |
|---|---|---|---|
| `POST` | `/api/ingest` | 上传 1–6 张图 + 备注 + 日期，立即返回 202 | iOS / macOS / Web |
| `GET` | `/api/batches?limit=6` | 最近批次列表 | Web「最近上传」 |
| `GET` | `/api/batch/{id}` | 批次详情（图 + 分科条目） | Web 详情、排障 |
| `POST` | `/api/batch/{id}/rerun` | 重新识别，不重传 | Web |
| `DELETE` | `/api/batch/{id}` | 删除批次（上传错了要能撤） | Web |
| `GET` | `/api/day?date=` | 某天全部作业，三态 `empty/pending/ready` | **TV 主接口**、Web 调试页 |
| `GET` | `/api/days?from=&to=` | 区间内每天有无作业 | TV 日期条圆点 |
| `GET` | `/img/{date}/{file}` | 原图 | 全端 |
| `GET` | `/api/health` | 健康检查 | 你 |

## 2. 数据库

SQLite 单文件，放在数据目录下（`data/hw.db`），WAL 模式。

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- 一次上传 = 一个批次。一天可以多个批次
CREATE TABLE batch (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  date       TEXT NOT NULL,              -- YYYY-MM-DD，Asia/Shanghai
  note       TEXT,                       -- 老师配文，可空
  status     TEXT NOT NULL DEFAULT 'pending',
                                         -- pending|ocr|parsing|done|failed
  error      TEXT,                       -- status=failed 时的原因，给人看
  created_at TEXT NOT NULL               -- RFC3339 +08:00
);
CREATE INDEX idx_batch_date ON batch(date);
CREATE INDEX idx_batch_created ON batch(created_at DESC);

CREATE TABLE image (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  batch_id INTEGER NOT NULL REFERENCES batch(id) ON DELETE CASCADE,
  path     TEXT NOT NULL,                -- 相对路径：2026-11-12/318_1.jpg
  sha256   TEXT NOT NULL,                -- 软去重用
  width    INTEGER NOT NULL DEFAULT 0,
  height   INTEGER NOT NULL DEFAULT 0,
  ocr_raw  TEXT,                         -- 单图 OCR 原文
  ocr_at   TEXT
);
CREATE INDEX idx_image_batch ON image(batch_id);
CREATE INDEX idx_image_sha ON image(sha256);

-- item 是派生数据，rerun 时整批删除重建，所以不要在这里放用户产生的状态
CREATE TABLE item (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  batch_id INTEGER NOT NULL REFERENCES batch(id) ON DELETE CASCADE,
  image_id INTEGER REFERENCES image(id) ON DELETE SET NULL,
  subject  TEXT NOT NULL,                -- 中文科目名，原样展示
  content  TEXT NOT NULL,
  sort     INTEGER NOT NULL DEFAULT 0    -- 科目内顺序
);
CREATE INDEX idx_item_batch ON item(batch_id);

-- 打勾状态单独一张表，因为它是用户数据，rerun 时不能丢
CREATE TABLE checkin (
  item_key   TEXT PRIMARY KEY,           -- sha256(subject + content)，跨 rerun 稳定
  done       INTEGER NOT NULL DEFAULT 0,
  done_at    TEXT
);
```

三个设计理由：

1. **`item` 可重建、`checkin` 不可重建**。`rerun` 会清空 `item` 重新生成，如果打勾状态存在 `item.done` 上，
   重跑一次孩子的勾就全没了。所以打勾按内容哈希存在独立表里。
2. **`image.sha256` 做软去重**。同一张图重复上传不报错，返回 `duplicate_of`，前端不用特殊处理。
3. **`width/height` 存下来**。电视端按宽高比预留位置，否则图加载完会跳版，3 米外看着很难受。

## 3. 图片存储布局

```
data/
├── hw.db
└── 2026-11-12/
    ├── 318_1.jpg      # {batch_id}_{序号}.{ext}
    └── 318_2.jpg
```

按日期分目录：备份时按天拷、删历史时按天删，都不用查库。文件名前缀用 batch_id，
任何一个文件都能反查到归属批次。
