# 国际化

> 目标：系统语言是英文时整个 App 呈现英文，其余语言回退英文；中文环境下保持现有中文体验。

## 1. 语言与回退

| 语言 | 代码 | 角色 |
|---|---|---|
| English | `en` | **默认 / 回退语言** |
| 简体中文 | `zh-Hans` | 仅 `zh` 环境启用 |

为什么默认语言设成英文而不是中文：非中文用户（德语、日语…）看到英文至少能猜，看到中文完全无解。

各端判定规则：

| 端 | 判定 |
|---|---|
| Android TV | 系统资源限定符：`values/` = 英文，`values-zh/` = 中文。不加任何运行时代码 |
| iOS / macOS | `Base` / `en.lproj` = 英文，`zh-Hans.lproj` = 中文；`developmentRegion = en` |
| Web | `navigator.language` 以 `zh` 开头 → 中文，否则英文；用户可用角落的 `中文 / EN` 切换，存 `localStorage` |
| Go 服务端 | `Accept-Language` 含 `zh` → 中文，否则英文 |

App 内部**不做语言切换器**（Web 除外）。跟随系统是正确行为，多一个开关只会多一条 bug 路径。

## 2. 应用名

| | 中文 | English |
|---|---|---|
| 显示名 | 家里的田字格 | `Tianzige` |
| 副标题 | 今日作业 / 课后作业 / 作业上传 | `Homework` |

`Tianzige` 保留拼音是刻意的：这个词没有对应英文，硬译成 "grid notebook" 反而更费解。
README 里用一句话解释它是什么（见 §7）。目标机器上已安装的中文版不会因为改语言而改包名。

## 4. 科目名

服务端存的、返回的都是中文科目名（`语文`/`数学`/`英语`/`科学`/`道法`/`其他`）。
**服务端不改数据结构**，由各端在显示层做映射：

| 服务端值 | English |
|---|---|
| 语文 | Chinese |
| 数学 | Math |
| 英语 | English |
| 科学 | Science |
| 道法 | Civics |
| 其他 | Other |

规则：
- 中文环境：原样显示
- 英文环境：查表；查不到（老师写了别的科目，如"美术"）→ **原样显示中文**，不要显示 "Unknown"
- 排序仍按服务端顺序，客户端不重排

为什么不在服务端做：科目名同时是 `checkin` 表的主键组成部分（`sha256(subject + content)`）。
改服务端返回值会让已打勾的记录全部失配。

## 5. 日期与时间

| 场景 | 中文 | English |
|---|---|---|
| 今日标题 | 今天的作业 | Today's homework |
| 昨日标题 | 昨天的作业 | Yesterday's homework |
| 其他日期标题 | 11月9日的作业 | Homework for Nov 9 |
| 相对角标 | 3 天前 / 3 天后 | 3 days ago / in 3 days |
| 日期条 | 周一…周日 | Mon…Sun |
| 完整日期 | 2026年11月12日 星期三 | Wed, Nov 12, 2026 |
| 上传时间 | 17:32 | 17:32（24 小时制，两边一致） |

实现要求：**用系统本地化 API，不要手拼字符串**。
- Android：`DateTimeFormatter.ofLocalizedDate(FormatStyle.MEDIUM).withLocale(locale)`，星期用 `DayOfWeek.getDisplayName(TextStyle.SHORT, locale)`
- iOS/macOS：`DateFormatter` + `Locale.current`，相对时间用 `RelativeDateTimeFormatter`
- Web：`Intl.DateTimeFormat(undefined, {...})`

中文的 `11月9日` 不要变成 `11月 9 日`（不要多空格），英文的 `Nov 9` 不要变成 `Nov 09`。

## 6. 错误文案

服务端返回的 `message` 是中文，**双语环境下不能直接展示给英文用户**。两级处理：

1. **服务端**按 `Accept-Language` 返回对应语言的 `message`（见 §8）
2. **客户端**优先按 `code` 用自己的文案，`message` 只作兜底

错误码 → 英文文案：

| code | 中文 | English |
|---|---|---|
| `bad_request` | 请求有问题 | Something's wrong with the request |
| `invalid_date` | 日期格式不对 | That date doesn't look right |
| `too_many_files` | 一次最多 6 张 | Up to 6 photos at a time |
| `file_too_large` | 单张不能超过 20MB | Each photo must be under 20 MB |
| `unsupported_type` | 只支持 jpg/png/heic/webp | Only jpg, png, heic or webp |
| `not_found` | 找不到这个记录 | Not found |
| `ocr_failed` | 这次没识别出来 | Couldn't read this one |
| `parse_failed` | 整理作业时出错了 | Couldn't sort out the homework |
| `llm_unavailable` | AI 服务暂时不可用 | The AI service isn't available |
| `internal` | 服务出了点问题 | Something went wrong on the server |

## 7. 英文语气

原则：**短句、具体、像跟人说人话**。避免 Let us / Please kindly / There is no…。

| 不要 | 要 |
|---|---|
| There is no homework today. | No homework yet today. |
| Upload successful. Processing in progress. | Got 3 photos. They'll be on the TV shortly. |
| Failed to upload, please try again. | Couldn't upload — tap to retry. |
| OCR result for reference only. | Recognized text — always check the photo. |
| Server address configuration | Server address |

破折号用 `—`（em dash），不用 `--`。句子结尾不强制句号（短标签不加，整句加）。

## 8. 服务端本地化

新增 `internal/i18n`：

```go
// Msg 返回本地化文案。lang 只区分 zh / en，其余归 en。
func Msg(lang, key string) string
// Lang 从 Accept-Language 解析，缺省 en
func Lang(r *http.Request) string
```

`writeError(w, status, code, messageKey, lang)` 或让 `writeError` 内部取 `Accept-Language`。
**所有现有硬编码中文 message 都要走 i18n**，包括 `ai.go` 里那几条（`请从 NAS 上传页打开 AI 设置` 等）。

`provider_test_failed` 的 message 来自上游 `err.Error()`，属于不可翻译内容，原样返回并在前面加一句本地化的前缀：
- 中文：`模型测试没通过：{err}`
- 英文：`The model didn't respond: {err}`

Web 端的 AI 设置页直接展示 message，所以这一块的本地化是必须的，不能只靠客户端映射。

## 9. 各端资源位置

| 端 | 文件 |
|---|---|
| Android TV | `app/src/main/res/values/strings.xml`（en）、`values-zh/strings.xml`（zh） |
| iOS | `Tianzige/Resources/en.lproj/Localizable.strings`、`zh-Hans.lproj/Localizable.strings`、`InfoPlist.strings` |
| macOS | `Sources/Resources/en.lproj/…`、`zh-Hans.lproj/…` |
| Web | `upload.html` / `today.html` 内联 `const I18N = { en: {...}, zh: {...} }` |
| Server | `internal/i18n/messages.go` |

Android 的 `app_name` 也走资源：`values/strings.xml` 写 `Tianzige`，`values-zh/strings.xml` 写 `家里的田字格`。

## 10. 验收

| 检查 | 方法 |
|---|---|
| 英文环境无中文残留 | `adb shell setprop persist.sys.locale en-US`（或模拟器改语言）后逐屏截图；iOS 用 Scheme → App Language → English |
| 中文环境无英文残留 | 同上切回中文 |
| 科目映射 | mock 数据里放 `语文/数学/英语/美术`，确认英文下前三个翻译、「美术」原样 |
| 日期格式 | 英文下标题是 `Homework for Nov 9`，不是 `Homework for 11月9日` |
| 错误文案 | 故意停掉服务端，确认两端提示都是当前语言 |
| 服务端 | `curl -H "Accept-Language: en" .../api/day` 与 `zh` 对比 |
